# Reorder safety (B2/B4/B5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Destructive reorder moves warn, reordered chains stay level-safe (already proven — verify), and feedback tails never smear across a reorder.

**Architecture:** Pure transition function for the toast, wired through the existing expiring footer message; order-change observation in `DspChain` clearing only recirculating audio buffers; B4 is verify-and-close (its test and measurement table already ship).

**Tech Stack:** Rust, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-reorder-design.md`

## Global Constraints

- No heap allocation, blocking, or locking on the audio thread; order observation reuses the seqlock read, clearing is memset-class writes to owned buffers.
- Move semantics otherwise unchanged: ends refuse, off-board stages hold slots, cursor follows its stage; refusals stay silent.
- Gates before push: `cargo fmt --check`; `cargo clippy --all-targets --all-features -- -D warnings`; `cargo test --release`; `cargo test`; `cargo run --release --example fidelity_render -- --check docs/fidelity/baseline-synth-48k.toml` (must stay green with zero baseline edits — no tone moves here).
- Work directly on `main`; never push unprompted.

## Review Focus

- Preset apply introducing mono-after-cab: no toast (only `[`/`]` wires it); the authored order applies unchanged — pinned by `preset_mono_after_cab_applies_silently` in Task 1.
- Rapid repeated `[`/`]` on an introducing move: the footer message refreshes (overwritten + TTL reset), never stacks — pinned by `repeated_introducing_moves_refresh_one_toast` in Task 1.
- Reorder with a loud ringing tail: the cut must not itself click — output stays finite with no full-scale step across the clearing block — pinned by `cleared_tail_does_not_click` in Task 2.
- Direct `set_chain_order` with stereo-before-amp (UI would refuse): applies as authored (sanitize deliberately passes it) — pinned by `authored_mono_collapse_applies` in Task 2.
- Take bus tails: cut by the same shared path as live — pinned by noting the shared code path in Task 2 (one implementation, both chains).
